# Fastlane Setup for Expo Prebuild

This document explains how Fastlane files are preserved during `expo prebuild` operations.

## Problem

When running `expo prebuild`, the `android` and `ios` directories are completely regenerated, which overwrites any existing Fastlane files (`Gemfile`, `Fastfile`, etc.) that are needed for CI/CD pipelines.

## Solution

We use a **native directory structure** to preserve Fastlane files across prebuild operations:

```
project-root/
├── native/
│   ├── android/
│   │   ├── fastlane/
│   │   │   ├── Appfile
│   │   │   └── Fastfile
│   │   ├── Gemfile
│   │   ├── Gemfile.lock
│   │   └── debug-gemfile.sh
│   └── ios/
│       ├── fastlane/
│       │   ├── Appfile
│       │   └── Fastfile
│       ├── Gemfile
│       └── Gemfile.lock
├── android/ (generated by prebuild)
├── ios/ (generated by prebuild)
└── scripts/
    ├── prebuild.sh
    └── post-prebuild.sh
```

## How It Works

1. **Fastlane files are stored in `native/` directories** - These are never touched by `expo prebuild`
2. **Custom prebuild script** - `scripts/prebuild.sh` runs `expo prebuild` and then restores Fastlane files
3. **Post-prebuild restoration** - `scripts/post-prebuild.sh` copies files from `native/` to generated directories

## Usage

### For Development
```bash
# Use the custom prebuild script (recommended)
npm run prebuild

# Or run manually
./scripts/prebuild.sh
```

### For CI/CD
```bash
# Platform-specific prebuild
npm run prebuild:android
npm run prebuild:ios

# Or run the post-prebuild script after expo prebuild
expo prebuild --platform android --clean
./scripts/post-prebuild.sh
```

## Scripts Available

- `npm run prebuild` - Full prebuild with Fastlane restoration
- `npm run prebuild:clean` - Standard expo prebuild (no restoration)
- `npm run prebuild:android` - Android prebuild with restoration
- `npm run prebuild:ios` - iOS prebuild with restoration

## CI/CD Pipeline Integration

In your GitHub Actions or CI pipeline, use:

```yaml
- name: Prebuild with Fastlane
  run: |
    npm run prebuild:android  # or prebuild:ios
    # Fastlane files will be automatically restored
```

## File Structure

### Android Fastlane Files
- `native/android/fastlane/Fastfile` - Android build and deployment lanes
- `native/android/Gemfile` - Ruby dependencies for Fastlane
- `native/android/Gemfile.lock` - Locked dependency versions

### iOS Fastlane Files
- `native/ios/fastlane/Fastfile` - iOS build and deployment lanes
- `native/ios/Gemfile` - Ruby dependencies for Fastlane
- `native/ios/Gemfile.lock` - Locked dependency versions

## Benefits

1. **Preserves Fastlane files** - No more missing Gemfile errors in CI
2. **Version controlled** - All Fastlane files are in git
3. **Platform specific** - Separate configurations for Android and iOS
4. **CI/CD ready** - Works seamlessly with GitHub Actions and other CI systems
5. **Developer friendly** - Simple npm scripts for common operations

## Troubleshooting

### Fastlane files missing after prebuild
- Ensure you're using `npm run prebuild` instead of `expo prebuild`
- Check that files exist in `native/android/` and `native/ios/`
- Verify script permissions: `chmod +x scripts/*.sh`

### CI pipeline fails with "Gemfile not found"
- Update your CI to use `npm run prebuild:android` or `npm run prebuild:ios`
- Or add `./scripts/post-prebuild.sh` after `expo prebuild` commands

### Files not being copied
- Check that the `native/` directories contain the expected files
- Verify the script has execute permissions
- Check the script output for error messages
